1. Objetivo do sistema

O iFácil será um painel administrativo para gerenciar um bot de atendimento. A primeira entrega é a tela de entrada do painel, responsável por receber as credenciais dos usuários administrativos. O projeto foi preparado para crescer aos poucos, sem concentrar toda a aplicação em um único arquivo.

Escopo atual: a interface do login está pronta. A autenticação ainda é visual; nenhum usuário é consultado em banco de dados e nenhuma API foi conectada.

3. Criação da base

O arquivo package.json registra o nome do projeto, dependências e comandos. Os scripts principais são:

"scripts": {
  "dev": "vite",
  "build": "vite build",
  "preview": "vite preview",
  "lint": "eslint ."
}
  • npm run dev: abre o ambiente de desenvolvimento.
  • npm run build: gera a versão otimizada na pasta dist.
  • npm run preview: visualiza localmente a versão de produção.
  • npm run lint: verifica a qualidade do código.

O plugin do Tailwind é registrado no vite.config.js. No CSS, @import "tailwindcss"; disponibiliza todas as classes utilitárias.

4. Organização das pastas

ifacil-frontend/ ├── docs/ documentação do projeto ├── public/ arquivos públicos futuros ├── src/ │ ├── components/ │ │ ├── auth/ │ │ │ └── LoginForm.jsx formulário e seu comportamento │ │ ├── brand/ │ │ │ └── BrandLogo.jsx identidade visual provisória │ │ └── ui/ │ │ ├── FormField.jsx campo reutilizável │ │ └── Icons.jsx ícones SVG │ ├── pages/ │ │ └── LoginPage.jsx composição completa da página │ ├── App.jsx ponto de composição da aplicação │ ├── index.css estilos globais e Tailwind │ └── main.jsx montagem do React no HTML ├── eslint.config.js ├── index.html ├── package.json └── vite.config.js

A separação segue o princípio de responsabilidade única: cada arquivo possui uma função clara. Componentes genéricos ficam em ui; componentes ligados à autenticação ficam em auth; páginas completas ficam em pages.

5. Fluxo da aplicação

  1. O navegador abre o index.html, que contém o elemento <div id="root">.
  2. main.jsx encontra esse elemento e monta a aplicação React.
  3. App.jsx carrega a página LoginPage.
  4. LoginPage combina a marca, o conteúdo institucional, os ícones e o formulário.
  5. LoginForm controla a interação de mostrar ou ocultar a senha.
function App() {
  return <LoginPage />
}

Manter o App pequeno facilita adicionar um roteador no futuro, por exemplo para alternar entre login, dashboard, atendimentos e usuários.

6. Construção da página de login

A página utiliza uma grade com duas colunas em telas grandes. A coluna esquerda apresenta o produto em fundo verde escuro; a direita exibe o formulário sobre fundo claro.

Identidade visual

  • Verde: ações principais, marca, foco dos campos e área institucional.
  • Vermelho: pequenos pontos de atenção e destaque, sem competir com a ação principal.
  • Branco e cinzas claros: formulário, leitura e contraste.

A marca atual é provisória e construída com elementos CSS. Ela pode ser substituída pela logo oficial em SVG ou PNG sem alterar o restante da página.

Conteúdo institucional

A lista de benefícios é guardada em um array e renderizada com map. Isso reduz repetição:

const benefits = [
  'Atendimentos centralizados em um só lugar',
  'Gestão simples, rápida e segura',
  'Acompanhamento da equipe em tempo real',
]

{benefits.map((benefit) => (
  <li key={benefit}>{benefit}</li>
))}

A propriedade key ajuda o React a identificar cada item de forma estável quando a lista for atualizada.

7. Componentes criados

BrandLogo

Componente responsável pela representação da marca. A propriedade light permite utilizar a mesma logo tanto em fundo escuro quanto claro:

<BrandLogo light />  // versão para fundo verde
<BrandLogo />       // versão para fundo claro

FormField

Reúne rótulo, ícone e campo. Ele recebe as configurações e repassa as propriedades para o input. Assim, e-mail e senha mantêm o mesmo padrão visual e de acessibilidade.

<FormField
  id="email"
  name="email"
  type="email"
  label="E-mail"
  icon={EmailIcon}
  autoComplete="email"
  required
/>

LoginForm

Contém os campos e comportamentos específicos do login. O hook useState guarda se a senha deve aparecer:

const [showPassword, setShowPassword] = useState(false)

type={showPassword ? 'text' : 'password'}

Ao clicar no botão, o React inverte o valor atual. A interface é renderizada novamente e o tipo do campo muda.

O envio usa event.preventDefault() para impedir o recarregamento tradicional da página. Na integração futura, a mesma função validará os dados e fará a chamada à API.

Icons

Os ícones foram implementados como SVGs locais. Isso evita adicionar uma biblioteca apenas para quatro símbolos, reduz dependências e dá controle total sobre tamanho e cor. Como são decorativos, usam aria-hidden="true".

8. Tailwind CSS e responsividade

O Tailwind trabalha com classes pequenas e específicas. Alguns exemplos:

ClasseEfeito
min-h-screenAltura mínima igual à tela inteira.
lg:grid-cols-[...]Cria as duas colunas somente em telas grandes.
hidden lg:flexEsconde a seção institucional no celular e mostra no desktop.
hover:bg-emerald-700Escurece o botão quando o mouse passa sobre ele.
focus:ring-4Exibe um anel visual quando o campo recebe foco.
transitionSuaviza mudanças de cor, posição e sombra.

A estratégia é mobile first: as classes sem prefixo valem para celulares; sm:, lg: e xl: acrescentam adaptações conforme o espaço aumenta.

9. Acessibilidade

  • Cada campo possui label associado por htmlFor e id.
  • Botões possuem type="button" quando não devem enviar o formulário.
  • O botão da senha muda seu aria-label entre “Mostrar senha” e “Ocultar senha”.
  • Elementos interativos apresentam foco visível para navegação pelo teclado.
  • autoComplete ajuda gerenciadores de senha e navegadores.
  • Os textos e fundos foram escolhidos buscando contraste confortável.

10. Validação e qualidade

O formulário já usa validações nativas:

  • type="email" exige formato semelhante a um e-mail.
  • required impede o envio vazio.
  • minLength="6" exige ao menos seis caracteres na senha.
Importante: validação no navegador melhora a experiência, mas nunca substitui a validação no backend. Dados recebidos pela API sempre devem ser validados novamente.

As verificações realizadas terminaram sem erros:

✓ npm run lint — código aprovado pelo ESLint.
✓ npm run build — versão de produção gerada corretamente.
✓ npm audit — nenhuma vulnerabilidade encontrada na instalação inicial.

11. Como executar o projeto

Abra um terminal na pasta do projeto e execute:

npm install
npm run dev

O Vite informará o endereço, normalmente http://localhost:5173. Para encerrar, volte ao terminal e pressione Ctrl + C.

Para testar a versão final:

npm run build
npm run preview

Conclusão

O projeto agora possui uma base moderna, executável e preparada para expansão. A separação entre página, formulário, marca, campos e ícones reduz acoplamento e facilita manutenção. A próxima evolução pode acontecer sem reescrever o que já foi construído: basta conectar o formulário à autenticação e iniciar a estrutura interna do painel.
